2. fractional knapsack
algo{
Sort the items by value per pound (v_i / w_i) in decreasing order
Let a_1, a_2, ..., a_n denote the items in this order
Let W be the knapsack capacity
Set total_value = 0
Set remaining_capacity = W
For j = 1, 2, 3, ..., n
    If remaining_capacity = 0 then
        Break
    Endif
    If w_j <= remaining_capacity then
        Take all of item a_j
        total_value = total_value + v_j
        remaining_capacity = remaining_capacity - w_j
    Else
        Take a fraction of item a_j
        fraction = remaining_capacity / w_j
        total_value = total_value + fraction * v_j
        remaining_capacity = 0
    Endif
Endfor
}

3. recursive weighted interval scheduling
algo{
Sort the intervals by their finish times in nondecreasing order
Let I_1, I_2, . . . , I_n denote the intervals in this order,
    with each I_j having start time s_j, finish time f_j, and value v_j
For j = 1, 2, 3, . . . , n
    For each interval I_i that precedes I_j in sorted order and overlaps it
        Exclude I_i from consideration as p(j)
    Endfor
    If there is any interval I_i that has not been excluded then
        Let p(j) be the largest index i < j such that I_i and I_j are disjoint
    Else
        Set p(j) = 0
    Endif
Endfor

Compute-Opt(j)
    If j = 0 then
        Return 0
    Else
        Return max(v_j + Compute-Opt(p(j)), Compute-Opt(j - 1))
    Endif
End
Invoke Compute-Opt(n) to obtain OPT(n)
}
- theorem(6.1): OPT(j) = max(vj + OPT(p(j)), OPT(j − 1)).
- theorem(6.2)only if Request j belongs to an optimal solution on the set {1, 2, . . . , j} if and v_j + OPT(p(j)) ≥ OPT(j − 1).
- theorem(6.3): Compute-Opt(j) correctly computes OPT(j) for each j = 1, 2, . . . , n.
Proof(6.3): By deﬁnition OPT(0) = 0. Now, take some j > 0, and suppose by way of induction that Compute-Opt(i) correctly computes OPT(i) for all i < j. By the induction hypothesis, we know that Compute-Opt(p(j)) = OPT(p(j)) and Compute-Opt(j − 1) = OPT(j − 1); and hence from (6.1) it follows that OPT(j) = max(v_j + Compute-Opt(p(j)), Compute-Opt(j − 1)) = Compute-Opt(j).

4. memoization weighted scheduling:
algo{
Sort the intervals by their finish times in nondecreasing order
Let I_1, I_2, . . . , I_n denote the intervals in this order,
    with each I_j having start time s_j, finish time f_j, and value v_j
Initialize array M[0 . . . n] with all entries set to "empty"
Set M[0] = 0
For j = 1, 2, 3, . . . , n
    For each interval I_i that precedes I_j in sorted order and overlaps it
        Exclude I_i from consideration as p(j)
    Endfor
    If there is any interval I_i that has not been excluded then
        Let p(j) be the largest index i < j such that I_i and I_j are disjoint
    Else
        Set p(j) = 0
    Endif
Endfor

M-Compute-Opt(j)
    If j = 0 then
        Return 0
    Else if M[j] is not empty then
        Return M[j]
    Else
        Define M[j] = max(v_j + M-Compute-Opt(p(j)), M-Compute-Opt(j - 1))
        Return M[j]
    Endif
End
Invoke M-Compute-Opt(n) to obtain OPT(n)
}
- theorem(6.4): The running time of M-Compute-Opt(n) is O(n) (assuming the input intervals are sorted by their ﬁnish times).
Proof(6.4): The time spent in a single call to M-Compute-Opt is O(1), excluding the time spent in recursive calls it generates. So the running time is bounded by a constant times the number of calls ever issued to M-Compute-Opt. Since the implementation itself gives no explicit upper bound on this number of calls, we try to ﬁnd a bound by looking for a good measure of “progress.” The most useful progress measure here is the number of entries in M that are not “empty.” Initially this number is 0; but each time the procedure invokes the recurrence, issuing two recursive calls to M-Compute-Opt, it ﬁlls in a new entry, and hence increases the number of ﬁlled-in entries by 1. Since M has only n + 1 entries, it follows that there can be at most O(n) calls to M-Compute- Opt, and hence the running time of M-Compute-Opt(n) is O(n), as desired.

7. 0-1 knapsack problem:
algo{
Sort the items arbitrarily (or by index 1, 2, . . . , n)
Let I_1, I_2, . . . , I_n denote the items in this order,
    with each I_j having weight w_j and value v_j
Initialize a two-dimensional array M[0 . . . n, 0 . . . W]
For w = 0, 1, 2, . . . , W
    Set M[0, w] = 0
Endfor
For i = 1, 2, 3, . . . , n
    For w = 0, 1, 2, . . . , W
        If w < w_i then
            Exclude the value of including I_i from consideration
            Set M[i, w] = M[i − 1, w]
        Else
            Let include_value = v_i + M[i − 1, w − w_i]
            Let exclude_value = M[i − 1, w]
            If include_value has not been excluded by the weight constraint then
                Assign M[i, w] = max(exclude_value, include_value)
            Else
                Leave M[i, w] as M[i − 1, w]
            Endif
        Endif
    Endfor
Endfor
Return M[n, W]
}
-theorem(6.11): If w < w_i then OPT(i, w) = OPT(i − 1, w). Otherwise OPT(i, w) = max(OPT(i − 1, w), v_i + OPT(i − 1, w − w_i)).
